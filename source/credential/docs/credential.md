# How the credential driver works

The rules, and why each one is there. A host that links the library gets all of them.

- **A secret is the file of that name** in the credentials directory. A name is what systemd allows for `LoadCredential=`: letters, digits, `-`, `_` and `.`, starting with a letter or a digit, no `/`, at most 128 characters. The directory is read-only to the driver; nothing is written, cached or logged.
- **The directory** is refused when it is a symlink, when group or others can write it, or when neither the uid of the process nor root owns it. Whoever can write there can put a credential of their own in it. Root counts as an owner only for the directory systemd made, which is the one `$CREDENTIALS_DIRECTORY` names (the same inode once canonicalised): systemd chowns that directory to the service user only where the filesystem has no ACL support, and where it has, the directory stays `root:root` `0550` and the service user is granted read by a POSIX ACL (measured on Ubuntu 26.04, systemd 259). A directory named with `--dir` that is not that one must be owned by the uid of the process.
- **A file** is refused (`rule`) when others have any access, when group can write, when neither the uid of the process nor root owns it, and when group can read unless the file carries an access ACL that is no more than what systemd makes: version 2, named-user entries only for the uid of the process, and no named-group entry that grants read. With an ACL the group bits of the mode are the ACL mask (acl(5)), so a clear group-write bit means that no entry can write, and the one bit an ACL can show in group is the read that systemd grants the service user.
- **A symlink** is refused in the path and as the file (`bound`): a credential is a plain file. So is anything that is not a regular file, and a file over 64 KiB.
- **The file is opened with `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)`**; where that answers `ENOSYS` (systemd's `RestrictSUIDSGID=yes`, or a kernel older than 5.6) and only then, with `openat(O_NOFOLLOW)`: a name is one component, so the two refuse the same things, and the owner, mode and type checks are made on the open descriptor either way. The tests run every case on both roads. The open is `O_NONBLOCK`, so that a FIFO cannot hang the worker thread.
- **The label** is made of the modification time (seconds and nanoseconds), the size and the inode, never of the value, so it moves when the file is replaced and tells nothing about the secret.
- **`Verify`** reads every credential in the directory by the rules of a `Read` and drops the values, so that a directory systemd made in a way the driver refuses is found at start (`source-credential check`) and not by the first call.
- **The capability is `NONE`.** A credential cannot change under a running service.
- **No guard on the socket** beyond its mode, in the thin main. A host that guards its sockets registers `Service(dir).router()` on a server of its own.
- **Linux only.** The crate does not build elsewhere, and its manifest says so.

The backend suite (`suite::run_temp`) holds the cases only a directory of credentials shows: the label, the absent credential, the names it refuses, a file open to group or others, links in and out of the directory, a directory as a credential, an oversized file, a label that moves with the file, and the checks on the directory.
