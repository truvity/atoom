# How the sqlite driver works

What it does and does not do, for a consumer that links it.

- **One SQLite file** (`index.sqlite`) below the state directory holds the whole index, under one declaration of kinds and columns. The directory must be a real directory (not a symlink), owned by this process's user and closed to others (mode no wider than 0750). It is checked at every start.
- **Tables.** `meta`: the tokenizer and the canonical text of the declaration. `cursor`: one row per log, the last verified checkpoint, moving forward only by a conditional write. `record`: one row per entry with the fixed columns, the entry once, and one column `c_<name>` per declared column (`TEXT` or `INTEGER`, `NULL` where a row has no value), unique by scope, log kind, log, tenant and hash, so that indexing an entry twice is a no-op; a database index per filter column. `record_fts`: the full-text table, external content over `record`, tokenizer `unicode61` with `remove_diacritics 2` and no stemming, holding only the declared word columns; none when no column is a word column.
- **The index is derived data.** A file of another schema version, another tokenizer or another declaration is refused at the start: the way is a rebuild from the logs, not a migration. A file of 0.8.0 or before (schema version 1, audit's fixed columns) is refused the same way.
- **The read side runs on connections opened read-only** (`query_only`), a small pool of them, so that no query can write whatever it holds; the write side has one connection under a mutex and runs each `Apply` as one immediate transaction.
- **A query is a keyset query**: newest first by time and then by arrival, the page token carrying the last row's time and id, so that pages do not shift while the index grows. The default page is 50 rows and no page is larger than 200.
- **Words become quoted phrases** of the FTS5 expression, so that no FTS5 operator, column filter or special character of the person's text means anything; a trailing `*` makes a prefix; at most 16 words of at most 64 bytes.
- **Bounds.** At most 1024 rows in an `Apply`, an entry of at most 1 MiB, a text value of at most 1024 bytes, at most 100 tenants, 32 partitions and 16 matches in a query.
- **The blocking calls run on the blocking threads** of the runtime (`spawn_blocking`), so a slow disk does not stall the server.
- **Who may call** each socket is decided by the [socket guard](../../../docs/socket-guard.md) of the thin main: by default the uid of the process; `--allow-uid` names the callers of the write socket and `--read-allow-uid` those of the read socket. A host that names its callers registers the routers on servers of its own.
